# 弱网连接与性能验证

在远控工具栏的“连接模式”中选择策略，选择会按设备保存，重连后继续使用：

- **低延迟（默认）**：优先降低码率，持续拥堵时降低传输分辨率；连续健康反馈后逐级恢复。
- **文字清晰**：保留原始分辨率，帧率上限 30，保留更多文字细节。
- **画质优先**：保留原始分辨率，帧率上限 45，保留更高码率下限。

画质和自定义 FPS 仍是上限。自适应缩放需要新版桌面纹理渲染器；旧客户端、软件数组渲染和录像期间保持原始尺寸。缩放不改变操作系统分辨率和鼠标坐标。

## 发送、解码和文件传输

每个显示器只采集一次，观看端使用独立编码器、码率和帧率反馈。发送忙时跳过尚未编码的画面；不会任意丢弃编码参考帧。每个观看端/显示器最多保留一帧待发送或待确认的数据，捕获重启也保留这个限制。

每个显示器另保留一份最新原始画面（GPU 路径保留独立纹理副本）。慢端恢复发送后，即使桌面已静止，也会补发最新画面；缓存不会随积压帧数增长。

客户端解码队列最多 6 帧；等待超过 200 ms 时清除整条依赖链、请求关键帧，再恢复解码。此限制针对应用队列，不包含操作系统 TCP 缓冲区和正在解码的单帧。

发送大帧期间仍处理输入。应用文件传输按同一设备共享预算：远控空闲时最高约 64 KiB/s，操作期间约 32 KiB/s，检测到拥堵时约 16 KiB/s；远控关闭后自动恢复。系统剪贴板驱动传文件不属于这条调度路径。

上传、下载和视频使用同一套排队延迟估计：从往返延迟中扣除学习到的基础 RTT。客户端通过服务端的延迟报告更新上传预算，稳定的高 RTT VPN 链路在基线建立后不会仅因 RTT 较高而持续限速。

独立编码会增加多个观看端同时连接时的编码负担；共享 CPU/GPU 饱和仍会影响所有会话。

## 重连与诊断

已建立会话发生临时网络故障后，按 1、2、4、8 秒间隔重试，最长约两分钟。关闭窗口或手动取消会停止重试。密码、权限、设备指纹变化和主动结束不自动重试；设备身份验证照常执行。

性能浮层显示最近一帧的采集、编码和发送/确认耗时，以及最近最多 120 帧的解码/渲染、排队 p95。瓶颈提示是启发式判断；这些耗时不能相加当作端到端延迟。静止画面显示“画面静止”，不会把网络延迟伪装成 0。

## 可重复验证

```powershell
cargo test --locked --lib --features flutter,hwcodec,vram server::video_
cargo test --locked --lib --features flutter,hwcodec,vram traffic::tests
cargo test --locked --lib --features flutter,hwcodec,vram client::video_queue
cd flutter
flutter test --no-pub
```

安装原生依赖后运行；本机也可用 `build/local-tools/native.cmd` 包装 Cargo。

两台设备的手工测试可使用透明 TCP 限速代理：

```powershell
python scripts/weak_network_proxy.py --target 192.168.1.20 --mbps 1 --delay-ms 80 --jitter-ms 40 --stall-every 10
```

控制端连接 `127.0.0.1:21120`，照常核对目标设备指纹和登录。代理仅监听本机、只接受私网或 Tailscale 目标，不解密数据。延迟是单向设置；停顿模拟 TCP 重传等待，不是真实 IP 丢包注入。

建议覆盖 LAN、4 Mbps VPN、1 Mbps 加抖动/停顿、慢解码，以及“一快一慢”两个观看端；测试拖动窗口、打字、静止画面、新观看端加入、并行传文件和断网恢复。记录首屏时间、输入响应、CPU/GPU 占用和浮层数据。

`weak_network_report` 是固定场景的 QoS 合成模型，可通过 `--ignored --nocapture` 运行，`SUBNETDESK_WEAK_REPORT` 指定 JSON 路径。它不模拟真实编码器、完整队列调度或两台电脑的实际响应时间，不能用其数值宣称整机性能提升。

## 主机记录与画面尺寸回归验证

登录成功后，主机记录按设备指纹独立保存到配置目录的 `recent_lan/`，不依赖“记住密码”。旧版 `_local.toml` 中的记录仍可读取；独立记录及删除标记优先，避免后台进程写入旧设置时丢失记录或恢复已删除的条目。

视频帧携带传输尺寸，尺寸改变时控制端重建解码器，避免硬件解码器继续使用旧尺寸的缓冲区。桌面几何尺寸、窗口大小和鼠标坐标仍取自显示器信息。控制端和被控端都需更新以完整启用此修复。

- 连接成功后关闭并重开应用，确认“最近连接”仍能找到主机；不记住密码时也应保留。
- 删除记录后修改设置、退出并重开，确认不会重新出现；再次成功连接则重新记录。
- 在弱网代理下观察传输分辨率降低与恢复，确认画面仍占据原显示区域，并检查四角的鼠标定位。

自动测试覆盖配置落盘、旧缓存覆盖、删除、设备地址变化，以及 VP9 多次降分辨率和恢复后的四象限图像内容。真实 GPU 渲染和双机弱网操作仍需实测。
