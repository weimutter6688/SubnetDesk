# 网络连接与安全审查

审查日期：2026-10-10。基线为主仓库 `2cbfaab55` 与共同库
`1d4cd763144e089a4db4b321096f657e4ea54207`。结论限于所述源码、测试及构建配置，
不能据此保证第三方依赖或所有运行环境不存在风险。

## 结论与范围

在当前 Windows 标准发行配置 `flutter,hwcodec,vram` 的已检查调用路径中，
未发现自动连接硬编码可疑公网域名、隐藏指挥控制服务器、反向 shell，或按
日期、用户名、主机名触发隐蔽破坏的代码。公网 rendezvous/relay、KCP、
WebRTC、自动公网更新和在线帮助连接已被移除或禁用。

检查仍发现实际缺陷：远端头像 URL 诱发额外请求；双向加密重复 nonce；
原生端口转发在认证后清除了加密；认证前资源限制不足。本次已修复这些问题。
发现缺陷本身不能证明作者有恶意意图。

覆盖 Rust 原生连接与认证、共同传输库、Flutter 头像入口、嵌入 Web 客户端、
Web 网关、监听/发现、服务恢复和相关命令执行入口。对已跟踪生产源码进行
域名/URL 字面量盘点，并人工检查网络构造、动态目标和调用路径。一次盘点
扫描了 486 个文件，新增连接辅助文件和测试也人工复核。字面量盘点不是可达性
证明，不能发现所有动态拼接或编码隐藏的内容；数字也不是依赖审计覆盖率。

没有完成第三方依赖逐行审计、供应链/二进制来源鉴定、真实设备抓包、跨平台
实机测试、完整认证 RDP 会话或实际安装/升级测试。

## 实际连接入口

| 入口 | 目标和触发方式 | 结果 |
| --- | --- | --- |
| 原生远控、文件传输等 | 用户输入/选择的 IP、主机名，及已知设备候选地址 | 直连，DNS 使用系统解析器，设备指纹仍需校验 |
| mDNS、UDP 发现 | 局域网组播/广播与响应地址 | 自动产生本地发现流量，无公网协调服务器 |
| Wake-on-LAN | 用户选择设备后发送唤醒包 | 明确功能入口 |
| 浏览器客户端 | 当前 `location.host` 的 `/ws` 与同源 `/api/info` | 当前站点，脚本/依赖嵌入应用，没有远程 CDN 加载入口 |
| Web 网关 | 本地监听，进入同一 LAN 握手/认证入口 | 可选启用，另有 HTTPS、来源、速率与连接配额校验 |
| IPC | Windows 命名管道或 Unix 本地套接字 | 本地进程间通信 |
| 原生端口转发/RDP | 已认证会话请求的被控端目标主机/端口 | 保留的正常转发功能，可访问目标侧可达服务，需要信任账号及权限 |
| 远端头像 | 过去接受已登录远端提供的 HTTP/HTTPS URL | 曾在本机 UI 请求该地址；现只接受内嵌图片或显示默认头像 |

用户输入的主机名、合法转发目标及系统 DNS 仍可能指向外部网络。当前 CIDR
白名单限制入站来源 IP，出站目标没有全部强制限制为私网。VPN 产品自身的
协调/中继连接也不属于本仓库的连接实现。

`src/ui_session_interface.rs` 的 `switch_sides` 为空实现。生成协议/FFI 中
保留相关名称不能当成已实现的隐藏反向连接。端口转发与远程终端则确实是
保留的认证后功能，不能因移除公网中继就认为它们不存在。

## 已修复问题

### 双向 nonce 重复

原来两端使用同一 secretbox 会话密钥，发送序号都从 1 开始，nonce 仅包含
序号，导致双向重复使用密钥与 nonce。修复前回归用例使用固定测试密钥证明：
两端发送相同明文会产生相同密文。这违反加密要求。

修复后 nonce 前 8 字节为小端 64 位序号，第 9 字节区分方向：客户端到服务端
为 0，服务端到客户端为 1。序号溢出时失败，禁止回绕。反射密文、重放帧、
未加密的空/单字节标记会失败；加密后的空明文仍合法。Rust 与 Web 使用相同
构造。LAN 线协议及签名握手前缀升级为 **v2**，明确拒绝版本不匹配，没有
退回 v1 的分支。**控制端和被控端必须一起更新**，浏览器页面需重新加载。
身份密钥、已保存指纹和账号不需重置；Flutter 到 Rust 的本地账号 JSON
格式仍为 v1，与网络线协议版本独立。

### 转发清除加密

原来原生端口转发在登录成功后，两端调用 `set_raw()` 清除了 LAN 加密，随后
转发原始字节。泛用转发协议可能暴露内容；RDP 自身可能采用 TLS，不能替代
LAN 隧道保证。修复保留密钥、分帧和收发序号，用 `send_raw()` 加密二进制
负载。与本地应用/目标服务之间的 TCP 字节流仍透明。共同 `Stream` 接口删除
清除加密和绕过加密发送的包装方法，检查脚本禁止转发入口重新引入这种调用。

### 头像诱发请求

登录请求中的 `avatar` 进入连接管理 UI；旧 `NetworkImage` 接受任意
HTTP/HTTPS URL，可用于追踪，或诱使本机请求内网地址。删除 URL 加载分支，
保留 `data:image/` 图片和默认头像。没有发现固定恶意域名，但动态请求入口
本身构成风险。

### 认证前资源限制

旧解析器限制初始预分配，却仍允许接近 1 GiB 的认证前帧声明。现握手与
服务端账号认证阶段入站帧上限为 **64 KiB**，超大头部立即拒绝；服务端授权
后才恢复正常协议上限，客户端成功交换密钥后恢复。

原生/Web 进入 LAN 认证的路径共享 **64 个未认证连接**配额，失败/关闭或
成功授权时释放。账号认证增加 **120 秒**固定期限，心跳不延长期限。
密钥交换仍使用现有读写超时。

这些措施不能保证抵御所有 DoS：原生配额是进程内全局限制，没有新增每来源
配额，攻击者仍可能占满；授权后的帧上限仍大。WebSocket/TLS/HTTP 外层
资源限制与 LAN 内层分别生效，64 KiB 不代表所有层的内存上限。现有 Web
网关另有全局 16、每来源 4 的 WebSocket 配额。

Web 网关过去在解析完成后才检查客户端消息的 256 KiB 上限，解析器本身却
允许 32 MiB，可能先分配/接收过大的数据。现将 WebSocket 入站帧和整条消息
上限都设为 256 KiB；只发超大帧头就立即失败。既有允许的客户端消息大小
保持一致，出站视频仍采用较大的上限。

## 网络优化

过去 DNS 未纳入超时，各解析地址串行获得完整超时。现在 DNS 与所有 TCP
尝试共用一个预算；地址去重，地址族内部保留顺序，交替 IPv6/IPv4，80 毫秒
后启动备用尝试，每端点最多两个并发。成功/超时会丢弃未完成连接。系统解析器
底层的阻塞工作可能继续到系统超时，应用不再等待它。

已知设备层另有最多两个候选端点的并发策略，两层合计最多四个 TCP 尝试。
这减少失效地址族和多地址主机等待，无法消除真实丢包或拥堵。

## 条件风险与逻辑触发

可选 `plugin_framework` 代码保留 HTTP 辅助函数和插件动态 URL。
`src/hbbs_http/http_client.rs` 非严格 TLS 探测可在失败后接受无效证书，削弱
身份验证。标准发行配置未启用该 feature，CI 禁止发布命令启用它。本次没有
改造整个未启用插件体系，也没有声称自定义插件版安全。以后启用前应移除
证书验证降级，重新审查插件来源和 URL 权限。

首次启动的默认账号 `subnetrust` / `subnet@local` 是公开共享凭据，符合来源
白名单的其他设备也可能使用。应在 LAN 设置中更换密码。默认允许网段较宽，
来源地址不能证明对端可信；账号与设备指纹校验仍必要。此行为已在 README
公开，本次未将其改为另一种初始化策略。

复核了进程退出、命令执行、定时器、墙上时钟和视频看门狗。观察用途为服务
安装/卸载/生命周期、提权、日志清理、证书时效，以及认证后的终端、重启、
文件和输入功能。未发现按日期/用户/主机名隐蔽破坏或外联的分支。Windows
视频看门狗使用单调时间和进展计数，仅在安装版、系统权限、后台服务监督的
`--server` 场景恢复；空闲/休眠恢复有保护，便携 UI 不执行该重启。恢复可能
中断会话，是已公开策略，不能仅因定时重启就认定逻辑炸弹。
